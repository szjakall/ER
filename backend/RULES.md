## 0. Chen 记法下画布可提供的语义信号

规则只能建立在**后端确实能拿到的数据**上。前端 `encode.ts` 会发送：

| 信号 | 来源 | 说明 |
|---|---|---|
| `element.shape` | 元素 | `rectangle` 实体 / `ellipse` 属性 / `diamond` 联系 |
| `element.label` | 元素 | 元素名称（实体名/联系名） |
| `element.attributes` | 实体、联系 | `string[]`；`*` 前缀=主键，`#` 前缀=部分键(弱实体鉴别器) |
| `element.is_weak` | 实体 | 弱实体标记 |
| `connection.from/to` | 连线 | 两端元素 id |
| `connection.type` | 连线 | `line` 普通 / `diamond_line` 联系分支 |
| `connection.cardinality` | 连线 | **Chen 记法单字符**：`1` / `N` / `M` / `P`（三元的第三端） 或 `null` |
| 全图快照 | `batch_check` | elements + connections 全集，用于全局规则 |

**关键设计：联系不是一条记录，而是"菱形元素 +2 条分支线"。**
「实体 A — 1 — ◇借阅 — N — 实体 B」在数据上 = 1 个 diamond 元素 + 2 条 diamond_line 连线。
因此"基数标注完整性""联系连通性"等规则必须基于**图结构**判定，而非单条连线。

## 1. 图形/元素级规则（单元素触发：element_added / element_modified）

| ID | 级 | 规则名 | 判定条件 | 提示语 |
|---|---|---|---|---|
| R01 | 刚性 | 元素必须有名称 | `label.strip()` 为空 | 「实体名称不能为空 —— 请为图形命名」 |
| R02 | 刚性 | 实体必须有主键 | shape=rect 且有属性但无 `*`；弱实体有 `#` 即豁免 | 「实体'{name}'缺少主键标注 —— 请在属性名前加 * 号」 |
| R03 | 刚性 | 属性必须填写名称 | shape=ellipse 且 label 为空 | 「属性必须填写名称」 |
| R04 | 刚性 | 联系必须标注名称 | shape=diamond 且 label 为空 | 「联系必须标注名称（如 借阅、属于）」 |
| R05 | 刚性 | 弱实体的键标注必须正确 | 弱实体缺 `#` 部分键；或同时标 `*` 与 `#`（概念混淆） | 「弱实体'{name}'缺少部分键…」/「…不应另标独立主键」 |
| R06 | 刚性 | 属性名不得为空项 | attributes 中存在空串或纯空白项 | 「实体'{name}'存在空白属性名」 |
| R07 | **启发** | 多个主键属性需确认 | 同一实体内多个属性带 `*`（可能是合法的复合主键） | 「…若为复合主键请确认无误，否则请只保留一个主键」 |
| R08 | 刚性 | 属性名不得重复 | 同一元素内去前缀后属性名重复 | 「属性'{name}'在实体'{owner}'中重复出现」 |
| R09 | **启发** | 属性名建议不与实体名相同 | 属性去前缀后 == 所属元素 label | 「…建议区分命名（如属性'学生'可改为'学生姓名'）」 |
| H01 | 启发 | 实体名建议用单数名词 | 实体名以「们」结尾，或英文复数 s 结尾 | 「实体名建议使用单数名词（如'学生'而非'学生们'）」 |
| H02 | 启发 | 联系名建议用动词 | 菱形名不含动词词表（**中性确认式**，业务惯例名可忽略；ISA 豁免） | 「联系名'{n}'不是常见的动词/动宾短语 —— …若为业务惯例命名（如'婚姻'）可忽略」 |
| H03 | 启发 | 疑似多值属性 | 属性名含 电话/邮箱/地址/多个/列表 等 | 「属性'{name}'可能为多值属性，建议拆分为独立实体或关联表」 |
| H04 | 启发 | 疑似派生属性 | 属性名含 年龄/总计/平均/总分/排名 等 | 「属性'{name}'可能是派生属性，建议标注为派生而非存储」 |
| H05 | 启发 | 同类元素命名风格应统一 | **仅同类元素内部**中英混用（实体名之间 / 属性名之间；跨类混用不报） | 「实体名中英文混用（中文 x 个、英文 y 个），建议统一命名风格」 |
| H06 | 启发 | 实体属性过多 | 单实体属性数 > 12 | 「实体'{name}'有 {n} 个属性，建议检查是否符合范式、是否需要拆分」 |
| H07 | 启发 | 名称含空格或分隔符 | 首尾空白；**中文名**内部空格；分隔符（括号/斜杠等）；英文名内部空格属正常 | 「名称'{s}'含多余空格或特殊字符，建议清理」 |
| H08 | 启发 | 名称过长 | 标签长度 > 20 字符 | 「名称'{name}'过长，建议精简」 |

## 2. 连线级规则（connection_added / connection_modified）

| ID | 级 | 规则名 | 判定条件 | 提示语 |
|---|---|---|---|---|
| R10 | 刚性 | 连线两端必须存在 | `from`/`to` 指向不存在的元素 id（悬空连线） | 「连线端点指向了不存在的元素」 |
| R11 | 刚性 | 禁止自环连线 | `from == to` | 「连线不能连接元素自身」 |
| R12 | 刚性 | 禁止重复连线 | 端点、类型、**基数全同**才算重复（递归联系两条分支基数不同，不算重复） | 「元素间已存在完全相同的连线（端点、类型、基数均相同）」 |
| R13 | **启发** | 实体间建议不要直接连线 | 两端 rectangle 且 `type=line`（可能是 ISA 继承，提示语注明可忽略） | 「…若是关联关系请用联系（菱形）表达；若是 ISA 继承则可忽略」 |
| R14 | 刚性 | 联系分支线必须标基数 | `diamond_line` 且缺基数；**仅当同菱形其他分支已标基数时**报（整体缺失由 R17 汇总，避免重复刷屏） | 「联系连线缺少基数符号（请在线上写 1 / N / M / P）」 |
| R15 | 刚性 | 基数必须是合法符号 | `cardinality` 不在 {1,N,M,P} 内 | 「基数'{v}'不合法 —— Chen 记法只允许 1 / N / M / P」 |
| R16 | **启发** | 普通连线不应标基数 | `type=line` 却写了 cardinality（操作失误，不损坏模型） | 「该连线不是联系分支线，基数只有写在联系分支线上才有意义，建议移除」 |
| H09 | 启发 | 实体间用联系分支线直连 | 两端 rectangle 且 `type=diamond_line`（与 R13 的 `line` 形态互不重叠） | 「实体间建议使用联系（菱形）连接」 |
| H10 | 启发 | 属性连线方向 | 属性与实体连线方向相反（实体指向属性） | 「属性归属连线建议由属性指向实体」 |
| H11 | 启发 | 联系分支线建议两端齐全 | 菱形仅有 1 条分支线（联系未连完） | 「联系'{name}'只连接了 1 个实体，建议补齐参与实体」 |

**小计 10 条**（刚性 5：R10–R12、R14、R15；启发 5：R13、R16、H09–H11）
